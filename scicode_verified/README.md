# scicode_verified/ — the SciCode-Verified dataset (SSOT + derived release)

This directory is governed by the **verify-with-human** gate. Two kinds of files live here:

## Source of truth (SSOT) — hand-edited, version-controlled
| path | what |
|---|---|
| `problems/<id>.json` | per-problem canonical state: prompts, sub-steps, `function_header`, `test_cases`, `return_line`. One file per problem. |
| `targets/<id>.json`  | per-problem target patches/transforms (only problems whose gold targets changed). Transform specs (`_type: ...`) regenerate target arrays at build time; `_rounds` lists the cleaning rounds applied. |
| `refs/`              | reference modules used by build transforms (e.g. `p13_ref.py` — the faithful #13 Maxwell reproduction that regenerates the corrected targets). |

**Only edit the SSOT.** Never hand-edit the derived files below.

## Derived — regenerated by script, never hand-edited
| path | produced by | what |
|---|---|---|
| `problems_test.jsonl` | `tools/assemble.py` | flattened release jsonl = concatenation of `problems/*.json`. The eval's `--data-dir`. |
| `manifest.json`       | `tools/assemble.py` | version + md5 of every released file (jsonl, per-target, `targets_set_md5`, `h5_md5`). The consumer verifies these md5s at startup and errors on mismatch. |
| `test_data_cleaned.h5`| `eval_clean/build_clean_h5.py` | the eval's `--h5py-file`: the original SciCode `test_data.h5` + the regenerated/patched targets. **Gitignored** (1.1 GB, rebuilt from the original h5 + `targets/`). |

## Rebuild / verify flow (after editing the SSOT)
```bash
python3 eval_clean/build_clean_h5.py      # SRC h5 + targets/ -> test_data_cleaned.h5  (only if targets changed)
python3 tools/assemble.py                 # problems/*.json -> problems_test.jsonl + manifest.json
python3 tools/verify.py --round <R> --scope <prompt|full>   # bidirectional gate; red light = no release
```
Decisions are recorded per change in `ledger/<round>.jsonl` (the audit trail). Deep/deferred
issues get a `ledger/BUG_*.md` / `NOTE_*.md` write-up.

## Deploy (sichuan2)
The eval runs on sichuan2 at `/data1/sihan/scicode-verified` (git-synced). To update:
`git pull` (gets SSOT + derived jsonl/manifest), then rsync `test_data_cleaned.h5` (not in git).
The remote h5 md5 must equal `manifest.json`'s `h5_md5` or the eval refuses to start.
